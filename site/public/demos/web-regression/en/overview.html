Web regression tests

Across ten applications, 34 cases passed in GitHub Actions and seven Shopify cases passed across separate Edge runs on Windows.

From cart to paid order in Shopify

Seven tests follow red and blue notebooks through variant selection, repeat additions, cart updates and checkout. The guest payment case matches checkout amounts to the paid test order recorded by the store.

  • SH-01Switch from red to blue before adding to cart
  • SH-02Carry quantities and subtotal into checkout
  • SH-03Remove blue and verify the checkout subtotal
  • SH-04Return from the cart and add a second blue notebook
  • SH-05Add the red variant twice
  • SH-06Reopen the cart in another tab
  • SH-07Match a guest checkout to the store order

Checking orders in WooCommerce

WooCommerce adds a storefront to WordPress. A shopper sees quantities and prices in the cart, while the store keeps a separate record of the order.

Three tests check cart totals after a quantity change, compare a purchase with the store’s order record and check which item receives a coupon discount.

  • WC-01Update the cart quantity
  • WC-02Match a purchase to the store order
  • WC-03Apply a product-specific coupon
  • WC-04Apply and remove a coupon on mobile
  • WC-05Reject an invalid coupon
  • WC-06Reconcile a discounted order

Publishing notices in WordPress

WordPress lets editors draft, publish and revise posts on a website. An editor might prepare a closure notice before making it public, or correct the opening time in a notice that readers can already see.

The tests check draft visibility, publishing, corrections and withdrawal, as well as registration links and category listings from the reader’s perspective.

  • WP-01Check who can read a draft
  • WP-02Publish a draft
  • WP-03Correct a post at the same URL
  • WP-04Follow a registration link on mobile
  • WP-05Withdraw a published notice
  • WP-06Move a post between categories

Submitting and grading assignments in Moodle

In Moodle, students submit coursework and teachers return grades and comments. Several students can submit the same assignment, each with a separate submission record.

Three tests compare a teacher’s download with the original file, check the student’s feedback screen and verify that grading one submission leaves the other ungraded.

  • MD-01Check a downloaded assignment
  • MD-02Read feedback as the student
  • MD-03Grade one student independently

Managing team files in Nextcloud

Nextcloud organizes team files in folders. When two departments use the same filename for a monthly report, the path matters as much as the name.

The tests move a Japanese-named file, restore a deleted file and edit one of two identically named files, checking the resulting paths and contents.

  • NC-01Find a file after moving it
  • NC-02Restore a file from the trash
  • NC-03Edit one of two identically named files

Managing everyday tasks in Vikunja

Vikunja organizes work by project. For example, a team member can add a task called “Review the monthly report materials” and mark it complete after checking the documents.

Four tests check that a Japanese task title is saved in the intended project, that completion survives a page reload, that submitting an empty title creates no task, and that completing one task leaves a task with the same title in another project open.

  • V-01Create a task in Japanese
  • V-02Reload a completed task
  • V-03Submit an empty title
  • V-04Complete one of two tasks with the same title

Managing invoice lines in Grist

Grist stores records in tables and uses formulas to calculate values. In this demo, each invoice line has an item name, a quantity and a unit price. A formula multiplies the quantity by the unit price to give the line total.

Three tests check that changing the quantity from 2 to 3 at a unit price of 2,500 gives a total of 7,500, that correcting a Japanese item name preserves the line ID and total, and that deleting one line leaves the other intact.

  • GR-01Recalculate an invoice line
  • GR-02Correct an item name
  • GR-03Delete one invoice line

Organizing documents in Paperless-ngx

Paperless-ngx helps teams file invoices, delivery notes and other documents by correspondent and tag. For example, a reviewer can tag a delivery note as “needs review” and later use that tag to find it.

Three tests check that a downloaded original matches the uploaded PDF byte for byte, that a document retains its assigned correspondent and tag, and that filtering by “needs review” returns only the tagged delivery note.

  • PL-01Retrieve the original PDF
  • PL-02Save a correspondent and tag
  • PL-03Filter documents by tag

Tracking development issues in Gitea

Teams use Gitea to host source code and track work on it. A developer can report a bug or request an improvement by opening an issue, then close the issue when the work is done.

Three tests check that a Japanese issue title and description are saved correctly, that a renamed issue can be found and closed, and that access to a private issue matches each user's permissions.

  • G-01Create an issue in Japanese
  • G-02Find and close a renamed issue
  • G-03Check private issue access

Tracking PC loans in Snipe-IT

Snipe-IT keeps an inventory of equipment and records who has each device. Each PC has its own asset ID, so two laptops of the same model can be lent out and tracked separately.

Three tests check that a PC is assigned to the intended borrower at checkout, that checking it back in clears the assignment, and that checking out one of two matching PCs leaves the other unassigned.

  • SN-01Verify an asset checkout
  • SN-02Check an asset back in
  • SN-03Check out one of two matching PCs
